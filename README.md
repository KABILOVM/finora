# Sumoima — личный учёт денег

Sumoima ведёт учёт ваших денег: кошельки (в том числе в разных валютах), категории, расходы, доходы, переводы между кошельками, остатки и курсы валют, а ещё бюджеты («сколько можно тратить в день»), цели накопления (сколько отложить к дате, сколько можно тратить в день и на чём сэкономить, чтобы успеть), регулярные платежи, долги с категориями, список покупок с памятью цен и импорт из Дзен-мани. Списки (бюджеты, долги, кошельки, регулярные платежи, покупки, аналитика) можно отфильтровать кнопкой «Фильтры».
Это сайт, который ставится на телефон как приложение (PWA) и **работает без интернета**: всё сохраняется на устройстве.
Если подключить облако (Supabase), данные сами синхронизируются между телефоном и компьютером.

- Интерфейс только на русском. Пользователей до 5, у каждого **свои** данные — друг друга они не видят.
- Деньги хранятся целыми числами в минимальных единицах (дирамы), поэтому копейки не «плывут».
- Записи не удаляются насовсем: «удалить» значит «скрыть». Это нужно, чтобы синхронизация не теряла данные.

## Два режима

- **Локальный** (по умолчанию, ключей нет): без входа, данные только на этом устройстве. Удобно просто посмотреть приложение. Обязательно делайте резервные копии.
- **С облаком**: вход по почте и паролю, данные синхронизируются. Включается двумя переменными, см. «Подключение облака». Если их нет или в них остались заготовки из `.env.example`, приложение честно работает локально.

## Запуск на своём компьютере

1. Установите [Node.js](https://nodejs.org) версии **22.12 или новее** (подойдёт LTS). Эта же версия записана в `package.json` (`engines`), по ней Vercel выбирает среду сборки.
2. В папке проекта выполните `npm install`. В проекте лежит файл `.npmrc` с настройкой `legacy-peer-deps=true` — она нужна, чтобы установка не спотыкалась о версии пакетов. Ничего менять не нужно.
3. Выполните `npm run dev` и откройте адрес из терминала (обычно http://localhost:5173).

## Подключение облака

Нужно один раз, примерно полчаса. Сделайте по порядку.

**1. Создайте проект Supabase.** Зайдите на supabase.com → New project. Проект должен быть **отдельным, только для Sumoima**: не берите проект другой системы (CRM и т. п.), иначе наши таблицы и правила добавятся в чужую базу.

**2. Создайте таблицы.** В проекте: SQL Editor → New query → вставьте **весь** файл `supabase/schema.sql` (не кусок!) → Run. Файл можно запускать повторно: ничего не удаляется и не дублируется. Это же — способ обновить уже созданный проект: в конец файла добавляются новые блоки (сейчас — предельная длина полей `color`, `icon` у кошельков и категорий и `fx_source` у операций, для списка покупок — таблица `shopping_items`, а для этапа 2 — таблицы `debts` (долги), `budgets` (бюджеты), `recurring_rules` (регулярные платежи) и две новые колонки у операций, `debt_id` и `recurring_rule_id`, а для целей накопления у кошельков — две колонки, `goal_minor` и `goal_on`, а для целей накопления в «Бюджетах» — таблица `savings_goals`, плюс колонки `essential` у категорий и `category` у долгов), и повторный запуск применит их к уже созданным таблицам, не трогая ваши данные. Тот же файл подходит и для проекта, настроенного на этапе 1: просто выполните его целиком ещё раз. Делать это нужно **до** того, как вы начнёте пользоваться обновлённым приложением: пока новых таблиц в облаке нет, синхронизация показывает ошибку и не может получить операции с других устройств (ваши данные при этом не теряются: всё остаётся на устройстве и синхронизируется после обновления базы). Если среди старых записей нашлась слишком длинная, файл не упадёт (Postgres выдаст предупреждение, но интерфейс Supabase может его не показать); новые и изменяемые записи ограничение проверяет в любом случае. **Цели накопления** (сумма и срок у кошелька-накопления) хранятся в облаке в колонках `goal_minor` и `goal_on`, их добавляет раздел 11 файла: выполните `schema.sql` целиком **до** выкладки приложения с целями. Если порядок нарушен, приложение не остановит синхронизацию (остальные кошельки, операции и прочие данные поедут как обычно), но кошелёк с целью, заданной до обновления схемы, — целиком, вместе с его операциями — останется на устройстве и уйдёт в облако после запуска файла; до этого статус синхронизации показывает ошибку с подсказкой выполнить `schema.sql`. **Города для погоды** (выбранный город и список, чтобы выбор был один на все устройства) хранятся в одной колонке настроек, `weather`; её добавляет раздел 13 того же файла — порядок тот же: сначала `schema.sql`, потом выкладка приложения (иначе настройки с выбранным городом — целиком, вместе с началом недели и кошельком по умолчанию — останутся на устройстве и уйдут в облако после запуска файла, а остальная синхронизация идёт как обычно; до этого статус синхронизации показывает ошибку с подсказкой выполнить `schema.sql`). **Проценты по долгам** (кредит в банке: сумма процентов, ставка и срок) хранятся в трёх колонках долга, `interest_minor`, `interest_rate_bp` и `term_months`; их добавляет раздел 14 — порядок тот же: сначала `schema.sql`, потом выкладка приложения (иначе долг с процентами — целиком, вместе с его операциями — останется на устройстве и уйдёт в облако после запуска файла, долги без процентов и всё остальное синхронизируются как обычно; до этого статус синхронизации показывает ошибку с подсказкой выполнить `schema.sql`). Для проверки версии при записи (см. «Известные ограничения») в схеме есть служебная колонка `base_seq` и условие в триггере; пока файл не запущен заново, синхронизация покажет ошибку. **Объединение долгов** (у каждого вошедшего долга остаются свои проценты, ставка, срок, даты, платежи и планы; в списке они идут одним долгом) хранится в одной колонке долга, `merged_into_id` (ссылка на главный долг); её добавляет раздел 15 — порядок тот же: сначала `schema.sql`, потом выкладка приложения (иначе объединённые долги — целиком, вместе с их операциями — останутся на устройстве и уйдут в облако после запуска файла, а остальная синхронизация идёт как обычно; до этого статус синхронизации показывает ошибку с подсказкой выполнить `schema.sql`, раздел 15). **«Обязательные» категории** (отметка у категории расходов: цели накопления в «Бюджетах» такие траты не урезают) хранятся в одной колонке категории, `essential` (0 или 1); её добавляет раздел 16. **Категории долгов** (короткий текст «Друзья», «Кредит» для списка и фильтра, не длиннее 40 символов) хранятся в одной колонке долга, `category`; её добавляет раздел 17. Для обеих колонок порядок тот же: сначала `schema.sql`, потом выкладка приложения. Если порядок нарушен, синхронизация не останавливается: категории без отметки и долги без категории едут как обычно (старое облако читается как «0» и «без категории»), а категория с отметкой «обязательная» и долг с категорией — вместе с их операциями — остаются на устройстве и уходят в облако после запуска файла; до этого статус синхронизации показывает ошибку с подсказкой выполнить `schema.sql` (разделы 16 и 17). **Цели накопления** в «Бюджетах» (название, сумма, срок и необязательная привязка к кошельку-накоплению) хранятся в отдельной таблице `savings_goals`, её создаёт раздел 18. Это новая таблица: пока файл не запущен, синхронизация показывает «В облаке не хватает таблицы» с подсказкой выполнить `schema.sql` целиком, поэтому раздел 18 нужно выполнить **до** выкладки приложения с целями.

**3. Настройте вход и регистрацию.** На экране входа есть кнопка «Нет аккаунта? Зарегистрироваться»: человек сам вводит почту и пароль (от 8 символов).
- Authentication → Sign In / Providers → Email: «Minimum password length» поставьте **8**. Приложение и так не даст задать пароль короче (ни при регистрации, ни при смене), но проверку на устройстве можно обойти — то же правило должен держать сервер.
- Authentication → Sign In / Providers → Email: «Allow new users to sign up» должен быть **включён**, иначе регистрация ответит «Регистрация отключена». Если круг должен быть закрытым — выключите его и создавайте людей вручную: Authentication → Users → Add user, отметка «Auto Confirm User».
- «Confirm email»: если включено, после регистрации человеку придёт письмо, и войти можно только после ссылки в нём. Встроенная почта Supabase шлёт письма только членам команды проекта, поэтому для друзей «Confirm email» лучше выключить — или подключить свой SMTP.
- Названия пунктов в Supabase иногда меняются, ищите похожие.

**4. Скопируйте ключи.** Project Settings → API (в новой панели раздел «API Keys»): нужны **Project URL** и **публичный ключ**: publishable key (раньше назывался anon). Создайте файл `.env` рядом с `package.json` по образцу `.env.example`:

```
VITE_SUPABASE_URL=https://ваш-проект.supabase.co
VITE_SUPABASE_ANON_KEY=sb_publishable_...
```

Эти же две переменные добавьте на хостинг. На Vercel: проект → Settings → Environment Variables. Файл `.env` в git не попадает.

> **Не путайте ключи.** На той же странице есть секретный ключ: `service_role` (в новой панели — «secret»). Он открывает всю базу в обход защиты, а всё, что лежит в `VITE_…`, вшивается в публичные файлы сайта — любой посетитель сможет его прочитать. Класть его в приложение **нельзя**. Если ошиблись: подставьте публичный ключ, пересоберите приложение, а старый секретный ключ считайте утёкшим и замените в панели Supabase. Если ошиблись с ключом, приложение не заработает как нужно: перепроверьте, что вставлен именно публичный.

> Если вы уже вели учёт без входа (локальный режим), **до** подключения облака сделайте резервную копию (Настройки → «Резервная копия»). После подключения облака приложение открывает данные аккаунта, а записи «без входа» остаются на устройстве отдельно. При первом входе на «Главной» и в «Настройках» появится плашка «Есть записи, сделанные без входа» с кнопкой «Перенести в аккаунт» — записи переносятся без дублей, а стартовые категории сливаются со стартовыми аккаунта. Если нажали «Не переносить», вернуть эти записи можно только из резервной копии.

**5. Пересоберите и выложите приложение.** Значения вшиваются в приложение при сборке, поэтому после любого изменения переменных нужна новая сборка. Локально: `npm run build`, готовый сайт лежит в папке `dist` (подойдёт любой хостинг с https). На Vercel: Deployments → Redeploy (Vercel сам понимает Vite: команда `npm run build`, папка `dist`). Адреса в приложении вида `…/#/settings`, поэтому настраивать перенаправления на хостинге не нужно.

> **Свой домен Supabase.** Если у проекта не стандартный адрес `….supabase.co`, а свой домен, ничего добавлять руками не нужно: при сборке адрес берётся из `VITE_SUPABASE_URL` автоматически и вписывается в политику безопасности страницы (CSP) в `index.html`: ровно этот адрес по `https` и `wss`, и больше никакие адреса Supabase. Поэтому приложение, которое при XSS попыталось бы отправить данные в чужой проект Supabase, упрётся в запрет браузера. Следствие: сменили `VITE_SUPABASE_URL` — **пересоберите** приложение (`npm run build` или Redeploy на Vercel), иначе браузер заблокирует новый адрес. Если переменных нет или в них заготовки из `.env.example` (локальный режим), адресов Supabase в политике нет вовсе. Адрес, из которого нельзя сделать безопасную запись в политику (например, с `;` или `*` в имени хоста), останавливает сборку с понятной ошибкой.

**6. Проверьте.** Откройте приложение, зарегистрируйтесь или войдите, добавьте операцию. В шапке должно быть «Синхронизировано». Если там «Только на устройстве» или нет входа — переменные не попали в сборку (вернитесь к шагу 5).

Что делает проверка: смотрит, что сервер отвечает и ключ в сборке не секретный; что вы вошли; что все таблицы и нужные колонки на месте; что свои данные читаются, а чужих не видно; что запись разрешена; что курсы на сервере читаются; сколько записей на устройстве ждут отправки. Таблиц в базе десять: девять ваших (`settings`, `wallets`, `categories`, `debts`, `budgets`, `recurring_rules`, `transactions`, `shopping_items`, `savings_goals`) и общая таблица курсов `exchange_rates`. Для проверки записи в каждую из девяти ваших таблиц отправляется одна **заведомо неверная** строка (пустое имя, сумма 0); сервер обязан её отклонить, поэтому в ваших данных ничего не меняется. Если вдруг строка пройдёт, проверка сама об этом скажет, а строка уже помечена «удалена» и в приложении не видна.

> Важно: облако проверялось только на эмуляторе PostgREST и на PGlite (настоящий Postgres в памяти), **не на живом Supabase**. Поэтому шаг 6 обязателен: он покажет, если что-то в вашем проекте настроено не так.

### Что проверка не умеет

«Все проверки пройдены» значит «всё, что мы можем проверить снаружи, в порядке». Два места снаружи проверить нельзя, поэтому их надо посмотреть самому:

- **Защита строк (RLS): чужие данные закрыты?** Проверка видит утечку, только если сервер показал вам чужую запись. Если вы единственный пользователь с данными, при выключенной защите результат такой же, как при включённой: «чужих записей не видно». Поэтому шаг «Чтение данных» прямо пишет, что подтвердить защиту не может. Убедитесь сами (см. «Как убедиться, что чужие данные закрыты» ниже).
- **Правка уже существующих записей.** Проверка проверяет права на вставку и обновление таблиц, но не пробует менять ваши настоящие записи (это изменило бы данные). Если по ошибке удалили только правило правки (политику `…_update_own`), проверка этого не заметит. Список правил смотрите в SQL ниже.

### Как убедиться, что чужие данные закрыты

Сделайте это один раз после настройки и после любого ручного изменения базы. В Supabase → SQL Editor выполните:

```sql
select tablename, rowsecurity
from pg_tables
where schemaname = 'public'
order by tablename;
```

Во всех десяти строках (`budgets`, `categories`, `debts`, `exchange_rates`, `recurring_rules`, `savings_goals`, `settings`, `shopping_items`, `transactions`, `wallets`) в колонке `rowsecurity` должно стоять `true`. То же видно в Table Editor: у каждой таблицы метка «RLS enabled».

```sql
select tablename, policyname, cmd
from pg_policies
where schemaname = 'public'
order by tablename, cmd;
```

Строк (только таблицы с данными и курсы, без напоминаний) должно быть **28**: по `INSERT`, `SELECT` и `UPDATE` (3 × 9 = 27) у `settings`, `wallets`, `categories`, `debts`, `budgets`, `recurring_rules`, `transactions`, `shopping_items`, `savings_goals` и одна `SELECT` у `exchange_rates` (ещё шесть строк у таблиц напоминаний — всего 34). Меньше — значит, `schema.sql` выполнен не целиком: запустите его заново (весь файл).

Самая надёжная проверка — на живых людях: когда добавите второго пользователя и он внесёт запись, откройте «Проверку облака» у первого. Если шаг «Чтение данных» не написал «ОПАСНО», а в приложении первого нет записей второго, защита работает.

## Проверка после выкладки

После каждой выкладки на хостинг проверьте заголовки ответа. Нужен `curl` (есть в терминале macOS и Linux, в Windows 10/11). Подставьте адрес своего сайта вместо `https://ваш-сайт`:

```
curl -I https://ваш-сайт/
curl -I https://ваш-сайт/sw.js
curl -sI "https://ваш-сайт/$(curl -s https://ваш-сайт/ | grep -o 'assets/[^"]*\.js' | head -1)"
```

Третья команда сама находит имя одного из файлов в `/assets/` на главной странице. Значения ниже взяты из `vercel.json`; на другом хостинге заголовки нужно настроить так же.

| Заголовок | `/` и `/sw.js` | `/assets/…` |
|---|---|---|
| `Cache-Control` | `no-cache` (браузер всегда спрашивает, нет ли новой версии) | `public, max-age=31536000, immutable` (имя файла меняется с каждой сборкой, поэтому его можно хранить год) |
| `Content-Security-Policy` | `frame-ancestors 'none'` | то же |
| `X-Frame-Options` | `DENY` | то же |
| `X-Content-Type-Options` | `nosniff` | то же |
| `Referrer-Policy` | `no-referrer` | то же |
| `Strict-Transport-Security` | `max-age=31536000` | то же |
| `Cross-Origin-Opener-Policy` | `same-origin` | то же |
| `Permissions-Policy` | камера и т. п. запрещены; микрофон — `(self)`: только само приложение, для «Продиктовать» в покупках и «Продиктовать операции» (не убирайте, иначе в Chrome и Edge запись не включится); геолокация — `(self)`: только само приложение и только по кнопке «Определить место» в погоде | то же |

В заголовке `Content-Security-Policy` — **только** `frame-ancestors 'none'` (запрет встраивать приложение в чужую страницу). Остальную политику браузер берёт из тега `<meta>` в `index.html`, собранного под ваш проект. Проверить её:

```
curl -s https://ваш-сайт/ | grep -o "connect-src 'self'[^;]*"
```

В облачной сборке там должны быть `'self'`, ваш адрес Supabase по `https://` и `wss://` и три источника курсов (`www.nbt.tj`, `cdn.jsdelivr.net`, `latest.currency-api.pages.dev`) и два адреса погоды (`api.open-meteo.com`, `geocoding-api.open-meteo.com`). Знака `*` и чужих адресов Supabase быть не должно. Если вместо вашего адреса пусто — в сборку не попали переменные `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` (шаг 5 «Подключения облака»).

Эти значения проверены только на раздаче, которая берёт заголовки из `vercel.json` (тесты `e2e/sec`), а не на настоящем Vercel, поэтому проверку выше стоит сделать самому. Если заголовки другие, значит `vercel.json` не подхватился: он должен лежать в корне проекта, рядом с `package.json`.

## Проверка в браузере (e2e)

`npm run test:e2e` сама собирает приложение в `dist`, запускает его на http://127.0.0.1:4173 и прогоняет сценарии в Chromium на двух «устройствах»: `iphone` (узкий экран) и `desktop`. Первый раз выполните `npx playwright install chromium`. Сценарии лежат в папке `e2e`:

- `e2e/flows` — работа человека с приложением: первый запуск, офлайн, валюты, переводы, правки, резервные копии, фильтры;
- `e2e/pwa` — манифест, сервис-воркер, хранилище, обновление версии;
- `e2e/sec` — безопасность: заголовки и политика безопасности страницы (CSP) в настоящем браузере, облачная сборка с поддельным ключом, права и ограничения в `supabase/schema.sql` (прогоняется в настоящем Postgres в памяти, PGlite, без Docker и без живого Supabase).

Один сценарий или одно «устройство»: `npx playwright test e2e/sec --project=desktop`. Параметры берутся из переменных окружения (`playwright.config.ts`): `E2E_PORT` — порт (по умолчанию 4173), `E2E_DIST` — папка сборки (по умолчанию `dist`), `PW_CHROMIUM_PATH` — путь к своему Chromium. Если запускаете несколько прогонов одновременно, дайте каждому свои порт, папку сборки и папку результатов, иначе они мешают друг другу:

```
E2E_PORT=4200 E2E_DIST=/tmp/finora-dist-a npx playwright test e2e/sec --output=/tmp/finora-results-a
```

Группа `e2e/sec` дополнительно собирает «облачную» сборку с поддельным ключом в папку `SEC_TMP`, а `e2e/pwa` держит свои временные сборки и профили браузера в `PWA_TMP` (по умолчанию обе в временной папке системы). Внешние адреса (курсы, Supabase) в `e2e/sec` и `e2e/pwa` подменяются заглушками, в живой Supabase тесты не ходят.

## Курсы валют

Приложение берёт курсы по очереди из трёх источников: с сервера Sumoima (таблица `exchange_rates`, если вы развернули функцию ниже), с сайта Нацбанка Таджикистана (nbt.tj) и из открытого интернет-источника. Любой курс можно задать вручную: Настройки → «Курсы валют» → «Свой курс» (он главнее всех остальных). Курс старше 3 суток приложение помечает как устаревший.

Порядок, по которому приложение выбирает курс для итогов: (1) ваш «Свой курс» из Настроек; (2) свежий курс из интернета (не старше 3 суток); (3) курс, который вы **ввели руками при внесении операции** (он запоминается как запасной, на экранах помечен «введён вручную ДД.ММ», итог со знаком «≈»; в Настройках → «Курсы валют» его можно сбросить); (4) устаревший курс из интернета. Введённый в операции курс никогда не перекрывает свежий курс из интернета. Сама операция всегда хранит тот курс, по которому внесена, и потом не переоценивается.

**Формат ответов nbt.tj и интернет-источника при разработке проверить вживую не удалось** (сеть была закрыта), разбор написан по предположению. После первого запуска нажмите Настройки → «Курсы валют» → «Обновить курсы» и **сверьте курс с сайтом Нацбанка**. Если не сходится или не обновляется — задайте свой курс.

Серверная функция `supabase/functions/fetch-rates` — необязательно. Она раз в сутки кладёт курсы в `exchange_rates`, и все устройства читают их оттуда. Как развернуть (подробности и готовый SQL — в комментарии в начале файла `index.ts`):
1. Supabase → Edge Functions → создайте функцию `fetch-rates`, вставьте в неё файл целиком; в настройках функции отключите «Verify JWT».
2. Edge Functions → Secrets: добавьте `CRON_SECRET` — длинная случайная строка без пробелов, не короче 32 символов.
3. Раз в сутки её нужно запускать: через расширения pg_cron и pg_net (SQL есть в начале файла) или любым внешним планировщиком (cron-job.org и т. п.). Время в cron — UTC.
4. Функция и расписание на живом Supabase не запускались — проверьте у себя: в «Проверке облака» шаг «Курсы валют на сервере» должен стать ✔, а «последняя дата» в нём — свежей (проверка берёт самые новые строки). Если дата не меняется несколько дней подряд, расписание не работает.

## Бюджеты, регулярные платежи, долги, импорт

- **Продукты** (на телефоне «Ещё» → «Продукты», на компьютере — в боковой панели): единый каталог из ~300 продуктов (овощи, фрукты, зелень, мясо, рыба, молочное, хлеб, крупы, масла и специи, напитки, сладкое, орехи и сухофрукты, дом и гигиена) с синонимами и падежами для поиска («картошки» находит «Картофель»). Данные каталога лежат в `src/domain/products/data.ts` (общие для всех, без цен), поиск — `catalog.ts`. Цены **личные**: «последняя» — цена за единицу в последней покупке, «средняя» — по покупкам за 90 дней (если их нет — по последним пяти), взвешенная по количеству. Считаются по купленным позициям списка «Покупки» и чекам (`stats.ts`, схема данных не менялась); «Картошка» и «Картофель» — один продукт. Названия, которых нет в каталоге, попадают в «Мои продукты». Начальных цен в каталоге нет: они появляются из ваших покупок. **«Что куплено» в «Новой операции»:** у расхода в категории «Продукты» (или её подкатегории) в кошельке основной валюты появляется необязательная строка «Что куплено». Продукты ищутся по каталогу и своим названиям (без набора показаны недавние), у каждого — количество, единица и **сумма за всё**; цена за единицу считается сама и сравнивается с прошлой и средней. Сумма операции равна сумме строк (поле суммы только для чтения, комиссии нет), сохраняется одним чеком через `ShoppingRepo.recordReceipt` (`PurchasesSheet.tsx`, `purchase.ts`); состав виден в окне расхода. Удалённый расход (и «Отменить» после сохранения) в цены не попадает. Названия приводятся к каталожным («картошка» → «Картофель»).
- **Подкатегории** («Настройки» → «Категории»): у категории можно указать «Входит в…» — тогда она подкатегория («Коммунальные услуги» → «Вода», «Свет»; «Семья» → «Жена», «Дети»). В интерфейсе один уровень: родитель и его дети. В списке дети стоят под родителем с отступом, при выборе категории у операции — сразу после родителя, с мелкой подписью родителя; цвет новой подкатегории по умолчанию как у родителя. Операцию можно внести и в сам родитель. Фильтр «Категория» по родителю показывает и операции его подкатегорий, лимиты и отчёты суммируют подкатегории в родителя. Родителя в архив убирают вместе с подкатегориями (в подтверждении об этом сказано), возвращают по одной. Категория с подкатегориями сама ни в какую другую входить не может. Данные: поле родителя `parent_id` у категории было и раньше (оно же приходит из Дзен-мани), схема и облако не менялись.
- **Бюджеты** (на телефоне «Ещё» → «Бюджеты», на компьютере — в боковой панели): лимит на месяц на категорию (с подкатегориями) или общий. Полоса и слова: «Потрачено 78%» (с 70% — предупреждение, с 90% — тревога, с 100% — «Превышен на …»). Лимит и траты считаются в основной валюте; операции по долгам в траты не входят, комиссия за перевод — входит («Комиссии»).
- **«Осталось на день»**: деньги на руках (кошельки вида «Накопления» не считаются) плюс регулярные доходы до конца периода, минус обязательное (регулярные расходы и переводы в накопления, ещё не проведённые и не пропущенные, — в том числе просроченные за последний месяц, — и долги «я должен» со сроком до конца периода), делённое на число дней. Период — до дня перед зарплатой, то есть самым крупным регулярным доходом (ищем на 45 дней вперёд), но не меньше чем до конца месяца и не меньше недели. Небольшой доход период не обрывает: если после него денег на день выходит меньше (например, потом аренда), показываем меньшую цифру. Доход, который должен прийти сегодня, но ещё не проведён, учитывается, но на сегодня можно не больше того, что на руках. Если задан общий лимит на месяц и по нему в день выходит меньше, крупно показываем цифру по лимиту — одинаково на «Главной» и в «Бюджетах»; регулярные расходы этого месяца из остатка лимита откладываются заранее. Комиссия регулярного перевода вычитается заранее. «Обычно вы тратите» — без регулярных платежей и трат с накоплений; проведённый сегодня регулярный платёж не считается «перерасходом дня». Правка регулярного платежа его неоплаченные даты не отменяет (как и «Просроченные» на экране платежей; даты до создания правила не берутся). Округляем вниз: больше, чем есть, приложение не обещает. Если по какой-то валюте нет курса, её деньги в расчёт не входят, а число помечено «≈». Как считается — написано на самом экране («Как это считается»).
- **Регулярные платежи**: расписание «каждые N дней / недель / месяцев / лет», месячное правило на 29–31 число в коротких месяцах срабатывает в последний день месяца. Предстоящие и просроченные — на экране и на «Главной»: «Провести» (можно поменять сумму), «Пропустить». Операция по расписанию всегда получает один и тот же номер для правила и даты, поэтому два устройства не проведут один платёж дважды.
- **«Проводить само»** (автоплатёж): проводит платёж, когда вы открываете приложение или возвращаетесь на вкладку. Только за последние 60 дней и не раньше дня создания или последней правки правила — всё старее остаётся в «Просроченных» для ручного решения. Нет свежего курса для валюты кошелька — не проводит и говорит об этом. На iPhone приложение не работает в фоне, поэтому платёж проводится при следующем открытии, а не ровно в день платежа.
- **«Завести «ЗП»»** («Регулярные платежи», карточка сверху, пока нет регулярного дохода-зарплаты): открывает обычное окно «Новый регулярный платёж» с заполненным: доход, раз в месяц, заметка «Зарплата» и категория «Зарплата» (если её не убирали); остаётся ввести сумму и выбрать день — число задаёт «Первый платёж» (29–31-го в коротких месяцах платёж придёт в последний день месяца). «Проводить само» по умолчанию выключено: зарплата ждёт в «Предстоящих», и вы подтверждаете приход кнопкой «Провести». Карточка исчезает, когда есть действующий регулярный доход в категории «Зарплата» или с заметкой «Зарплата» / «ЗП»; «Не нужно» убирает её на этом устройстве. **Сумма зарплаты фиксированная, а если пришла другая — укажите причину:** если в окне «Провести» изменить сумму регулярного дохода (кроме платежа по долгу), появляется обязательное поле «Причина изменения суммы» («премия», «больничный», «вычет»); операция записывается с новой суммой и заметкой «Зарплата (премия)». Само правило не меняется: в следующем месяце снова предложена обычная сумма. Постоянное изменение (повышение) — правкой самого платежа; причина там не записывается. У платежей «Проводить само» сумма всегда обычная, поле причины не нужно.
- **Долги** (раньше «Долги и кредиты»): «Мне должны» и «Я должен». Остаток не хранится, а считается из платежей. «Записать движение денег» создаёт операцию в кошельке (деньги уходят/приходят); эти операции не входят в доходы и расходы месяца. Платёж больше остатка требует подтверждения («Это переплата»). **Проценты** (кредит в банке, заём под процент): в «Новом долге» и в «Правке долга» галочка «Есть проценты» — ставка (% годовых) и срок (месяцев) сами считают проценты за весь срок равными платежами (аннуитет, как у большинства банков), а сумму можно поправить руками под договор. Остаток считается от «сумма долга + проценты»; на кошелёк приходит (или с него уходит) только сумма долга — проценты денег не двигают. На странице долга видно «Проценты», «Всего к возврату» и ставку со сроком, в «Платить частями» есть кнопка «По договору» (сумма с процентами поровну на срок). Долг с процентами не предлагается присоединить к уже заведённому долгу того же человека, а «Взял ещё в долг» процентов не пересчитывает — их можно поправить в «Правке долга». Пока процентов нет, всё работает как раньше.
- **Покупки** (на телефоне «Ещё» → «Покупки», на компьютере — в боковой панели): список с флажками, единицы шт / кг / л. Количество хранится целым в тысячных долях (1,4 кг = 1400), деньги — целыми минорными единицами. Отметили позицию — впишите цену с ценника (за всю позицию): под ценой появится цена за единицу («13,00 за л»). Неотмеченные показывают ожидаемую цену «≈» = последняя запомненная цена за единицу × количество. «План» — сумма ожидаемых цен ещё не купленных позиций; «Осталось на «Продукты»» — остаток бюджета категории за месяц (если он задан). «Подтвердить покупку» записывает ОДИН расход на сумму отмеченных (кошелёк и категория — самые частые) с «чеком»: состав виден в окне расхода в «Операциях». Цены списка — в основной валюте, поэтому кошелёк для покупки тоже в ней. Купленная позиция больше не меняется; удаление — мягкое (есть «Отменить»). Список входит в резервную копию.
- **Частые операции и «Повторить»** (форма «Новая операция» и «Правка операции»): в панели категорий (плитка «Категория») над сеткой появляется полоса «Часто вносите» с тем, что вы вносили снова и снова за последние 90 дней: тот же вид, кошелёк, категория, сумма и заметка, не меньше двух раз (до шести чипов, чаще — левее; число повторов — в подсказке чипа). Нажали чип — подставились кошелёк, категория, сумма и заметка, остаётся «Сохранить» (дата — сегодня). Пока ничего не повторялось, полосы нет. В счёт не идут переводы, движение денег по долгам, операции по расписанию, корректировки остатка и удалённые. Ничего отдельно не хранится: список считается из самих операций, поэтому одинаков на всех устройствах и не требует изменений в облаке. Операция с архивным кошельком или архивной категорией не предлагается. В «Правке операции» кнопка ↻ «Повторить» (в подвале, между «Удалить» и «Сохранить») открывает «Новую операцию» с теми же полями, что сейчас на экране (поправили сумму — повторится поправленная), и датой «сегодня»; у операций по долгам её нет.
- **Подсказки по заметке** («Новая операция»): набираете в «Заметке» начало слова, и вместо кнопки «Готово» появляется полоса чипов с тем, что вы уже вносили с такой заметкой за последний год: «Кофе с собой 20 с.». Совпадает начало заметки или начало любого её слова (середину слова не ищем). Нажали чип — подставились заметка, категория и кошелёк, а сумма — только если вы её ещё не набрали (набранное вами главнее подсказки). Подсказки показываются до трёх, сначала совпадения с начала заметки, потом те, что повторялись чаще и недавнее. Заметка закрывается, как и раньше: Enter, тап мимо или Esc. Подсказки только для расходов и доходов, у перевода их нет; операции по долгам, по расписанию, корректировки остатка и записи с архивной категорией или кошельком не предлагаются. Ничего отдельно не хранится: подсказки считаются из ваших операций на устройстве, в облаке менять ничего не нужно.
- **Ввод одной строкой** («Новая операция» → «Заметка»): напишите в заметке «такси 20 карта», «кофе 15 вчера» или «аренда 2к», и первым чипом (цветным, «Применить: …») появится разобранная строка: сумма, кошелёк, категория и дата. Нажали — всё подставилось (сумма из строки главнее уже набранной), а в заметке остаётся то, что не было суммой, кошельком или датой («такси в аэропорт»; если слово и есть категория, как «еда 30», заметка остаётся пустой). Как читается строка: ровно одно число (два числа — неясно, какое сумма, подсказки не будет) и ещё хотя бы одно слово; «2к» и «1,5к» — тысячи; неоднозначное «1,000» не угадывается; сумма читается в валюте названного кошелька (иначе выбранного в форме). Кошелёк — по названию целиком (хоть из нескольких слов) или по началу названия от трёх букв, если оно одно такое («нал», «карт»). Категория — по названию (целиком или словом внутри заметки), а если не нашлась, то по истории: привычная категория (и кошелёк, если он не назван) для такой же заметки. Даты: «сегодня», «вчера», «позавчера». Только для расходов и доходов. Работает на устройстве, без интернета и без ИИ, ничего не меняется, пока вы не нажали чип.
- **Пропущенные дни** («Главная», под строкой «Требует внимания»): если последние два дня подряд и больше (до вчера включительно) прошли без единой записи, появляется спокойная плашка «3 дня без записей — всё в порядке?» (месяц и больше — «Больше месяца…»). «Внести траты» открывает «Новую операцию» (расход) сразу на вчерашнем дне, плашка исчезает, как только внесли операцию. «Ничего не тратил(а)» отмечает дни до вчера как прошедшие без трат (есть «Отменить»), плашка уходит до следующего пропуска. Сегодняшний день не считается (он не закончился). Записью человека считается любая внесённая им операция, кроме операций по расписанию (их проводит приложение), корректировок остатка и удалённых; у нового человека, у которого записей ещё нет, плашки нет. Ответ «Ничего не тратил(а)» хранится **на этом устройстве** (как другие подсказки интерфейса), в облако не уходит: на другом устройстве плашка может появиться ещё раз. Схему облака менять не нужно.
- **Выгрузка списка операций в CSV** («Операции», значок со стрелкой вниз справа от заголовка): в файл `sumoima-operations-ГГГГ-ММ-ДД.csv` попадает ровно то, что сейчас в списке, с учётом периода, фильтров и поиска, и **все** найденные операции, а не только показанные на экране (по «Показать ещё»). Формат тот же, что у «Операции в таблицу (CSV)» в Настройках: UTF-8 с BOM, разделитель «;», суммы с запятой, названия вместо номеров, по возрастанию даты; заметки, которые Excel принял бы за формулу, помечаются апострофом. Операция по долгу в файле выглядит как обычный доход или расход (как и в полной выгрузке). Кнопки нет, пока в списке ничего нет. Ничего не отправляется: файл собирается на устройстве.
- **«Похоже на подписки»** («Регулярные платежи»): расходы одного кошелька, которые повторяются с одной и той же суммой раз в неделю, две недели или месяц (не меньше трёх платежей, суммы в пределах 5%) и ещё не заведены как регулярный платёж. «Создать платёж» открывает обычное окно с заполненными полями, «Не показывать» убирает подсказку на этом устройстве. У каждой подсказки видно, во сколько она обходится **за год** («В год ≈ 708 с.»: сумма × 12, 26 или 52), а в строке над списком — **общая сумма за год** по всем подсказкам, а не только по показанным тремя (по валютам кошельков, если они разные). Если подписка **подорожала**, под ней жёлтая строка «Подорожало: было 49 с., стало 59 с. (+20%)»: так считается, когда перед нынешней серией (не меньше трёх платежей по новой цене) был платёж или несколько на том же шаге и заметно дешевле, но не больше чем вдвое (скачок сильнее похож на пробный период или другой тариф). Удешевление не отмечается. Новая цена считается подтверждённой, когда по ней набралось три платежа; свёрнутая строка тоже говорит, сколько подписок подорожало. Всё считается на устройстве по вашим операциям, облако не затрагивается.
- **Аналитика → «Периоды»** (третья вкладка рядом с «Обзором» и «Календарём»): год, квартал или любые даты (не длиннее пяти лет; конец позже сегодняшнего подрезается) и сравнение — «с прошлым годом/кварталом», «с предыдущими днями» (такой же отрезок сразу перед выбранным), «тот же период год назад» или без сравнения. Идущий год и квартал сравниваются с **теми же числами** прошлого, а не с целым прошлым (иначе в начале года всё выглядело бы «на 90% меньше»); какие именно даты сравниваются, написано под итогами. В отчёте: расходы, доходы, разница и **норма сбережений** — доля дохода, которая не потрачена (целым процентом, отрицательная, если потратили больше; без доходов — «—»), каждое против сравниваемого периода («▲ +12% · в прошлом году 53 000 с.»); полоса **«Куда ушли деньги»** (весь доход поделён на пять самых крупных категорий расходов, «остальное» и остаток; расходы больше дохода — полоса это все расходы, превышение подписано); расходы и **доходы по категориям** с долей и сдвигом (для расходов рост красный, для доходов — зелёный; «новая», «нет трат»), по восемь с кнопкой «Показать ещё»; доходы и расходы по месяцам; «Главное за период» (самый затратный и самый доходный месяц, главная статья расходов, средний расход в месяц; нужно хотя бы два месяца). Суммы — по тем же правилам, что остальная «Аналитика»: в основной валюте по снимкам курса, переводы и операции по долгам не входят, операции в другой основной валюте пропускаются и пересчитываются отдельно (внизу итогов — «Не учтено N операций»). Выбор лежит в адресе (`?tab=periods&kind=quarter&year=2026&q=3&cmp=yoy`): «Назад», обновление страницы и ссылка его не сбрасывают. Всё считается на устройстве из ваших операций, облако не затрагивается.
- **«Что бросается в глаза»** (Аналитика → «Обзор», под «Темпом трат»): три вида находок в расходах выбранного месяца. **Необычно крупная трата** — больше любой из прошлых трат этой категории за пять месяцев и не меньше чем в 2,5 раза больше обычной (медианы); нужно хотя бы пять прошлых трат в категории, а сама трата — не меньше 5% расходов месяца (мелочь не показывается). **Новая статья расходов** — категория, на которую пришлось не меньше 10% расходов месяца, а за последние три месяца трат в ней не было (если расходы были хотя бы в двух из этих месяцев: у нового человека «новым» было бы всё). **Возможный дубль** — две и больше одинаковых трат (кошелёк, категория, сумма, заметка без учёта регистра) в один день; экран спрашивает, а не утверждает: две порции кофе по одной цене бывают. Не учитываются операции по расписанию, по долгам, корректировки остатка, переводы, удалённые, будущие и внесённые в другой основной валюте. У каждой находки «Открыть трату» / «К операциям» и «Скрыть» (помнится на этом устройстве, на другом находка может появиться снова). «Необычно много за месяц по категории» по-прежнему в «Темпе трат». Нет находок — нет карточки.
- **«Итоги недели»** («Главная», в начале недели): карточка про прошедшую неделю (понедельник — воскресенье) — сколько потрачено, как это против недели до неё («▲ +50% · неделей раньше 400 с.»), на какую категорию ушло больше всего (с долей), самая крупная трата и сколько получено. Появляется с понедельника по четверг и только если за неделю были расходы или доходы; с пятницы исчезает. «Подробнее» открывает «Аналитику → Периоды» на этих же датах (сравнение — с неделей до неё), «Скрыть» убирает карточку этой недели на этом устройстве. Всё считается на устройстве, уведомления не отправляются.
- **«Сверить все кошельки»** («Кошельки», кнопка под списком; когда кошельков больше одного): на одном экране все кошельки с остатком в приложении; вводите, сколько на самом деле (в банке или в кошельке), — в строке сразу видно «Совпадает» или «В приложении меньше на 200 с.: запишем +200 с.». Пустые строки пропускаются. «Записать корректировки · N» кладёт по каждому расхождению «Корректировку остатка» сегодняшним числом (она видна в истории, но не доход и не расход, см. «Сверить с банком» в сверке кошелька) и одним «Отменить» убирает все. Кошелёк не в основной валюте записывается по курсу из «Курсов»; нет курса — строка не записывается, понятно почему, остальные записываются. У кошелька с минусовым остатком (кредитка) есть переключатель «Минус (я должен банку)». Начальные остатки не меняются.
- **«Отложить остаток»** («Главная», с 1-го по 7-е число): если прошлый месяц закрылся с плюсом (доходы больше расходов, остаток не меньше 5% дохода), карточка говорит «За сентябрь 2026 осталось 1 200 с.» и предлагает перевести их на кошелёк-накопление: сначала в цель с ближайшим сроком, иначе в накопление без цели; откуда — обычный кошелёк с самым большим остатком в основной валюте (больше, чем на нём есть, не предлагается). «Отложить» открывает форму «Новая операция» с готовым переводом (сумму можно поправить), сам перевод не делается. «Не сейчас» убирает предложение этого месяца на этом устройстве; если в этом месяце уже был перевод на накопление, предложения нет. Накоплений в основной валюте нет — карточки нет.
- **«Проверка данных»** (Настройки → «Данные» → «Проверка данных»): показывает то, что похоже на ошибку внесения, ничего не исправляя само. **Возможные дубли** — одинаковые траты (кошелёк, категория, сумма, заметка) в один день за последние полгода; «Удалить лишнюю» оставляет одну (с «Отменить»). **Без категории** — расходы и доходы без категории за три месяца (первые пять, «Все без категории» ведёт в «Операции»). **Дата в будущем** — операции позже сегодняшнего дня (частая опечатка в годе). **Слишком крупные траты** — больше любой другой траты категории за год и не меньше чем в 10 раз больше обычной (лишний ноль). **Отрицательный остаток** кошелька. Каждую находку можно открыть («Исправить дату», «Проверить сумму», «Выбрать категорию», «Открыть кошелёк») или отметить «Это нормально» (помнится на этом устройстве); нет находок — «Проблем не найдено». Не проверяются операции по расписанию, по долгам, корректировки остатка и переводы.
- **«Итоги года» карточками** (Аналитика → «Периоды» → «Год», кнопка под итогами): девять слайдов, которые листаются пальцем, кнопками «Назад» / «Далее» или стрелками клавиатуры: вступление («Ваш 2026 год» / «итоги на сегодня», сколько операций внесено), деньги за год, норма сбережений (с прошлым годом), куда уходит больше всего (три главные категории), самый затратный и самый доходный месяц, самая крупная трата, день недели, по которому вы тратите больше всего (в среднем за такой день; нужно хотя бы 4 таких дня), самая длинная серия дней без трат (от трёх подряд; до первой записи года дни не считаются) и сравнение расходов с прошлым годом. Слайды без данных пропускаются; суммы выводятся как везде, поэтому «Скрыть суммы» их тоже прячет. Считается на устройстве.
- **«Разделить счёт»** («Долги», кнопка под переключателем): вы заплатили за всех — вносите общую сумму, выбираете кошелёк, категорию вашей доли, дату, заметку («ужин») и имена друзей (до девяти; имена подсказываются из ваших долгов «мне должны»). Делится поровну на вас и друзей, копейки, которые не делятся, остаются на вас. Записывается одной операцией базы: ваша доля — обычный расход с категорией, а на каждого друга — долг «мне должны» на его долю («Счёт: ужин») с выдачей денег из того же кошелька (в расходы выдача не входит, как и любая выдача в долг). Кошелёк уменьшается на весь счёт. Одинаковые имена не пропускаются; кошелёк не в основной валюте записывается по курсу (нет курса — поле для ввода). «Отменить» в уведомлении убирает расход, долги и их выдачи одним шагом. Если не получилось что-то одно, не записывается ничего.
- **Импорт из Дзен-мани** (Настройки → «Импорт из Дзен-мани»): читает CSV-файл на вашем устройстве, ничего никуда не отправляет. Показывает предпросмотр, сопоставление счетов и категорий, потом записывает. Повторная загрузка того же файла не создаёт дублей. **Формат файла Дзен-мани проверен только на выдуманных образцах** (настоящего файла не было): если не получилось, пришлите файл с вымышленными суммами. Начальные остатки новых кошельков — 0; после импорта сверьте остатки с банком и поправьте начальный остаток. Курсы за прошлые даты неизвестны: все операции в иностранной валюте пересчитываются по одному курсу, который вы вводите на экране импорта (на остаток кошелька это не влияет, на отчёты в основной валюте — влияет).

**Если облако уже подключено:** этап 2 добавил таблицы. Откройте `supabase/schema.sql` в Supabase → SQL Editor и выполните его заново целиком (он рассчитан на повторный запуск), затем войдите в приложение и внесите одну операцию: если синхронизация показывает «Синхронизировано», всё в порядке. **Важно:** берите `schema.sql` из той же версии приложения, которая выложена (из ветки `main`, когда этапы 2–3 влиты). Старая схема перезапишет проверку версий при записи (`base_seq`), и защита от потери правок с двух устройств перестанет работать.

## Вход по коду, замок Face ID и напоминания

Всё это работает только при подключённом облаке (кроме замка: он работает и локально). **Ничего из этого не проверено на живом Supabase и настоящем iPhone** — только эмуляторами, PGlite и виртуальным Face ID в Chromium; проверьте у себя по шагам ниже.

**Вход по коду на почту.** На экране входа переключатель «Пароль / Код на почту». Новых пользователей код не создаёт; на неизвестную почту человек видит тот же ответ, что и на известную (чтобы нельзя было узнать, кто зарегистрирован). Что нужно сделать в Supabase:
1. Authentication → Email Templates → «Magic Link» и «Confirm signup»: в письме должно быть `{{ .Token }}` — иначе придёт ссылка вместо кода, а входа по ссылке в приложении нет.
2. Встроенная почта Supabase шлёт очень мало писем в час и только членам команды проекта. Для постоянной жизни подключите свой SMTP: Authentication → SMTP Settings (бесплатные варианты — Resend, Brevo; у бесплатных тарифов есть дневной лимит — сверьте на сайте сервиса).
3. Authentication → Email: длина кода («Email OTP Length», приложение принимает 6–10 цифр) и срок его действия. «Allow new users to sign up» оставьте так, как решили в шаге 3 (вход по коду новых людей не создаёт в любом случае).

**Замок Face ID / отпечатком** (Настройки → «Блокировка приложения»). Это «замок на экран»: защищает, если кто-то взял ваш *разблокированный* телефон. Данные на устройстве при этом **не шифруются**, а проверка ключа делается на самом устройстве (сервера для неё нет) — от человека, который умеет менять код страницы, она не защита. Замок закрывается при запуске и когда приложение было свёрнуто дольше выбранного времени. Если не получается открыть: «Выйти и войти заново» (данные на устройстве сохраняются; в локальном режиме — «Снять замок»). На iPhone включайте замок в приложении, добавленном на экран «Домой». Для работы замка в `vercel.json` разрешён `publickey-credentials-get=(self)` — не убирайте. Если сменится адрес сайта, ключ замка перестанет подходить (выйдите и войдите заново).

**Удаление аккаунта сейчас ВЫКЛЮЧЕНО** (`ACCOUNT_DELETION_ENABLED` в `src/auth/deleteAccount.ts`): проект Supabase общий с другим приложением, а функция `delete-account` удаляет пользователя из общей таблицы входа, и вместе с ним каскадом уходят его профили в другом приложении. Кнопки в настройках нет; остаётся «Выйти и стереть данные устройства». Включать только после переезда Sumoima в отдельный проект. Описание ниже — для того момента. **Удаление аккаунта.** В «Настройки → Аккаунт → Удалить аккаунт…» человек сам стирает аккаунт и все свои данные в облаке (потом — данные устройства); для этого нужна серверная функция: у приложения нет права удалять пользователей. Supabase → Edge Functions → создайте функцию `delete-account`, вставьте файл `supabase/functions/delete-account/index.ts` целиком, **оставьте «Verify JWT» включённым**. Секреты добавлять не нужно (`SUPABASE_SERVICE_ROLE_KEY` платформа выдаёт сама). Пока функции нет, кнопка честно отвечает «ещё не установлено на сервере», ничего не удаляется.

**Напоминания (push).** Приложение подписывается на уведомления браузера и записывает подписку в облако; раз в час серверная функция `send-reminders` смотрит ваши данные и присылает: платежи по расписанию (кроме «Проводить само»), долги со сроком, и (по желанию) «внесите траты», если за день нет ни одной операции, и (по желанию, выключено по умолчанию) **лимиты бюджета**: когда расходы месяца дошли до 70% или 90% лимита или превысили его (один push на каждый лимит и уровень за месяц; считается так же, как на экране «Бюджеты»). Суммы в уведомление не попадают никогда (у лимитов — только процент); названия (платежей, имён, лимитов) — только если включить «Показывать названия». **На iPhone уведомления работают, только если приложение добавлено на экран «Домой» (iOS 16.4+).** Настройка:
1. На компьютере: `npx web-push generate-vapid-keys`. **Public Key** положите в переменную Vercel `VITE_VAPID_PUBLIC_KEY` и пересоберите (Redeploy). **Private Key** — только в секреты функции (ниже), никуда больше.
2. Supabase → SQL Editor: выполните весь `supabase/schema.sql` заново (раздел 9 добавляет три таблицы, раздел 10 — таблицу `shopping_items` для «Покупок», раздел 11 — колонки целей накопления у кошельков, раздел 12 — переключатель «Лимиты бюджета» и новый вид записи журнала, раздел 13 — колонка городов для погоды у настроек, раздел 14 — проценты по долгам, раздел 15 — объединение долгов; повторный запуск безопасен). **Если функция `send-reminders` уже развёрнута, после этого вставьте её файл заново и задеплойте:** старая версия про лимиты ничего не знает, а про проценты по долгам знает только новая — без неё напоминание о долге с процентами считало бы остаток без процентов.
3. Edge Functions → создайте функцию `send-reminders`, вставьте файл `supabase/functions/send-reminders/index.ts` целиком, отключите «Verify JWT». Secrets: `CRON_SECRET` (≥32 символов; тот же, что у `fetch-rates`), `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (`mailto:вы@почта`).
4. Расписание раз в час: pg_cron + pg_net — готовый SQL в шапке файла функции (время UTC). Проверка вручную — curl из той же шапки.
5. В приложении: Настройки → «Напоминания» → «Включить» → «Проверить уведомление».
Если уведомление не пришло: Настройки iPhone → Уведомления → Sumoima; режим «Не беспокоить»; логи функции в Supabase (в ответе функции есть счётчики и коды ошибок без личных данных). Выход из аккаунта отзывает подписку этого устройства, чтобы напоминания одного человека не приходили на экран другого. Если у двоих один телефон, напоминания идут тому, кто вошёл позже.

**Список покупок голосом (ИИ).** «Покупки» → «Добавить списком»: нажимаете «Продиктовать» (запись голоса прямо в приложении, с анимацией и таймером) или набираете текст; облачная функция `parse-shopping` слушает запись или читает текст через Gemini, результат видно до добавления. Микрофон нужно разрешить в Safari. Нужен вход в аккаунт. Настройка:
1. Бесплатный ключ: Google AI Studio → «Get API key».
2. Supabase → Edge Functions → создайте функцию `parse-shopping`, вставьте файл `supabase/functions/parse-shopping/index.ts` целиком («Verify JWT» можно отключить: токен функция проверяет сама).
3. Edge Functions → Secrets: добавьте `GEMINI_API_KEY` (необязательно `GEMINI_MODEL`, по умолчанию `gemini-3.8-flash`). Ключ хранится только там, в приложение и в репозиторий он не попадает.

**Операции голосом (ИИ).** «+» → «Продиктовать операции» (круглая кнопка с микрофоном справа от «Расход / Доход / Перевод»): рассказываете о деньгах за день (или набираете текст) — о расходах, доходах и переводах между своими счетами: «такси двадцать пять, получил зарплату пять тысяч на карту Алиф, снял с карты тысячу наличными, комиссия пять». Облачная функция `parse-expenses` через Gemini собирает список: вид (расход / доход / перевод), название, сумма, счёт (у перевода — «откуда» и «куда»), категория, дата, заметка и комиссия. Счёт и категория выбираются только из ваших (для дохода — из категорий доходов); если категории нет, предлагается новая (создаётся при сохранении). Не назван счёт — берётся счёт по умолчанию, это видно в строке; не назван счёт назначения у перевода — его нужно выбрать (строка подсвечена). Долги и обмен валюты голосом не вносятся. Каждую строку можно открыть и поправить (в том числе сменить вид: «Расход / Доход / Перевод»), потом «Сохранить»: каждая строка становится обычной операцией; у расхода комиссия прибавляется к сумме (и видна в заметке), у перевода списывается сумма плюс комиссия, а на счёт назначения приходит сумма; у дохода комиссии нет. Перевод поддерживается между счетами **одной валюты** (между валютами — вручную: «+» → «Перевод»). Для валютного счёта курс берётся автоматически, как в обычной форме (у перевода курс нужен только для комиссии); нет курса — строка подсвечивается. Запись до ~4 минут. Настройка та же, что для покупок: Edge Functions → функция `parse-expenses`, вставьте `supabase/functions/parse-expenses/index.ts` целиком (**при обновлении приложения функцию нужно выложить заново**: старая версия понимает только расходы, а новое приложение с ней продолжит работать, но доходы и переводы не распознает); секрет `GEMINI_API_KEY` общий.

**Чек по позициям (фото и ручной ввод; ИИ — только для фото).** «+» → «Продиктовать операции» → «Чек по позициям»: фотографируете чек (или выбираете снимок из галереи) — облачная функция `parse-receipt` через Gemini читает магазин, дату, итог и **позиции** (название, количество и единица шт/кг/л, цена за всю позицию) и предлагает категорию каждой позиции из ваших (нет подходящей — новая, создаётся при сохранении). Либо «Ввести вручную»: позиции вносите сами, ИИ не нужен. Всё можно поправить: название, количество, цену, категорию (значками и «Новая категория»), добавить или убрать позицию. Под списком — «Сумма позиций» и, если итог с чека распознан, сверка с ним («Позиций не хватает на 11,50 с.»: так видно пропущенную строку). **На каждую категорию записывается свой расход** (так один поход в магазин ложится на «Продукты», «Быт» и «Здоровье» по-честному: категории, бюджеты, отчёты работают как обычно), а сами позиции видны в «Чеке» каждого расхода (как у покупок из списка) и пополняют память цен списка покупок. В заметке расходов — магазин (при нескольких категориях ещё и название категории). Кошелёк — в основной валюте (цены чека в ней); дата — с чека, не позже сегодняшней. Расходы и позиции пишутся одной операцией базы (не получилось что-то одно — не записано ничего); «Отменить» в уведомлении убирает все расходы чека. Фото перед отправкой уменьшается до 1600 px по длинной стороне (JPEG), на сервер уходят только фото, названия ваших категорий расходов и сегодняшняя дата; фото нигде не хранится. Настройка: Edge Functions → создайте функцию `parse-receipt`, вставьте `supabase/functions/parse-receipt/index.ts` целиком; секрет `GEMINI_API_KEY` общий (необязательный `GEMINI_MODEL` — как у остальных). Без функции на сервере ручной ввод работает, а «Сфотографировать чек» скажет, что разбор ещё не установлен.

**Поездки.** «Ещё» → «Поездки» (на компьютере — в боковой панели, раздел «Планирование»): сколько ушло на поездку, по дням и категориям. Поездка — это **метка в заметке** операции: `#Самарканд` (2–40 букв, цифр, «_» или «-»; `#самарканд` и `#Самарканд` — одна поездка). Ничего нового в облаке и в схеме базы не нужно: метки лежат в заметках и ездят между устройствами вместе с операциями; помечать можно и вручную, дописав `#метку` в заметку любой операции (в том числе уже внесённой). «Начать поездку» включает **режим поездки** на этом устройстве (настройка устройства, в облако не уходит): пока он включён, форма «Новая операция» дописывает метку в заметку сама (обычная операция, голосом и «Чек по позициям»; в тосте «Сохранено · #Самарканд»), а на «Главной» висит карточка «Идёт поездка» с потраченным и кнопкой «Завершить». Список поездок — по дате последней операции, с суммой расходов; отчёт: потрачено, число дней и расход в день, категории с долями, расходы по дням, «Чем платили» (суммы в валютах кошельков, если было несколько валют), самые крупные траты и все операции поездки (тап открывает правку). Суммы — по снимкам основной валюты, как в «Аналитике»; долги, корректировки остатка и операции в иной прежней основной валюте в расходы поездки не входят (о последних сказано в отчёте).

**Шаблоны операций.** Готовые заготовки формы со своим названием: «Кофе — 15 с.», «Обед в столовой», «Аренда — 3 000 с.», «Снять наличные». Как завести: наберите «Новую операцию» (сумма, кошелёк, категория, заметка), откройте список категорий и нажмите «Сохранить как шаблон» (кнопка появляется, когда набрана сумма; под полями формы места нет, поэтому она в панели категорий) — приложение предложит название (заметка, иначе категория, иначе вид операции), форма остаётся открытой, сама операция не сохраняется. То же есть внизу правки любой прошлой операции (кроме операций по долгам): так заводятся и шаблоны-переводы (у перевода — «Откуда», «Куда» и комиссия сохраняются). Метки поездки (`#Самарканд`) в шаблон не попадают. Где пользоваться: (1) строка «Шаблоны» на «Главной» — нажатие открывает «Новую операцию» с готовыми полями (сумму можно поправить, дата — сегодня), так внесение занимает один тап и «Сохранить»; показываются первые восемь, остальные — по ссылке «Все»; (2) в панели категорий формы шаблоны этого вида (расход или доход) стоят первыми в строке «Шаблоны и частые» со звёздочкой, частая операция, уже сохранённая шаблоном, второй раз не показывается; (3) «Настройки» → «Шаблоны операций»: «Внести», «Переименовать», «Удалить» (с «Отменить»). Названия не повторяются без учёта регистра («Кофе», «кофе 2»), шаблонов не больше 30. Если кошелёк шаблона удалён или в архиве, а категория удалена, в архиве или другого вида, шаблон остаётся в списке с пометкой и не вносится, пока его не удалят или не заведут заново. Шаблоны хранятся **на этом устройстве** (отдельно для каждого человека, в облако не уходят и в резервную копию не входят): на другом телефоне их нужно завести заново. Новых таблиц и колонок в облаке не нужно.

## Установка на iPhone и Android

- **iPhone (Safari):** откройте сайт → «Поделиться» (квадрат со стрелкой) → «На экран Домой» → «Добавить».
- **Android (Chrome):** меню ⋮ → «Установить приложение» или «Добавить на главный экран».

Когда выходит новая версия, приложение покажет «Доступна новая версия» и обновится только после вашего «Обновить».

## Резервные копии — обязательно

Safari на iPhone может очистить данные сайта, который не открывали около недели. Установленное на экран «Домой» приложение надёжнее, но копии всё равно нужны — особенно в локальном режиме, где данных больше нигде нет.

- Сделать копию: Настройки → «Резервная копия» → «Скачать копию (JSON)». Положите файл в надёжное место (почта, облачный диск, компьютер). Делайте это регулярно, например раз в неделю.
- Вернуть данные: «Загрузить копию (JSON)». Копия объединяется с тем, что уже есть: побеждает более новая версия каждой записи, ничего не удаляется.
- Таблица операций для Excel: «Скачать операции (CSV)».
- Настройки → «Хранилище» → «Защитить данные от очистки», если кнопка есть.

## Оформление и лицензии

- «Стеклянная» тема: светлая, тёмная или «как в системе». Выбор — в Настройках → «Оформление»; там же **цвет акцента**: фиолетовый (по умолчанию, прежний вид), синий, бирюзовый, зелёный, оранжевый, красный или розовый. Акцент перекрашивает кнопки, выбранные пункты, карточку «Всего», фон и пятна на нём, а также знак «$» в шапке, на экране входа и в мастере настройки. И тема, и акцент хранятся на самом устройстве (`localStorage`) и в облако не уходят: на телефоне и на компьютере они могут быть разными.
- Цвета заданы токенами в `src/index.css`; у каждого акцента своя палитра для светлой и тёмной темы (блоки `data-accent`). Контраст текста не ниже WCAG AA для каждого акцента: `src/accents.test.ts` разбирает сам `index.css` и проверяет все пары цветов. Новый акцент — новый блок в `index.css` плюс строка в `ACCENTS` (`src/theme.ts`); тест подскажет, если контраст или список разошлись. Цвета знака «$» лежат там же (`--ac-logo-*`, рисует `src/components/Logo.tsx`), а вот значок приложения на экране «Домой» и иконка вкладки браузера (файлы в `public/`) остаются фиолетовыми: из приложения их не перекрасить.
- Шрифт Manrope (SIL OFL) лежит в `src/assets/fonts/`, иконки Solar (480 Design, CC BY 4.0) и Lucide (ISC) вшиты в `src/components/iconData.ts` — всё работает без интернета. Файл создаётся скриптом `scripts/gen-icons.cjs`.
- Значок категории или кошелька (поле `icon`) бывает «i:имя» (встроенная иконка; всего около 165, в окне выбора они разложены по разделам: семья и дети, дом и коммунальные услуги, еда, транспорт, здоровье и красота, покупки и одежда, отдых, работа и деньги — основные лежат в `src/components/iconData.ts`, дополнительные ~100 штук грузятся лениво из `src/components/iconExtra/`, их создаёт `scripts/gen-icons-extra.cjs`, как добавить значок — в шапке скрипта), «b:банк» (знак банка Алиф, Душанбе Сити или Хумо; список — `src/features/wallets/banks.ts`) или эмодзи из прежних записей: известные эмодзи показываются подходящей иконкой, данные не меняются. Знаки банков нарисованы упрощённо, это не официальные логотипы.
- Логотипы сервисов (Netflix, Spotify, Claude, ChatGPT, Gemini, Microsoft, Dropbox, PayPal, Visa, Binance, Telegram и ещё около 80 — подписки и платежи) хранятся в том же поле как «s:id», например «s:netflix», схема данных и облако не меняются. В окне категории и кошелька это вкладка «Сервисы» рядом с обычными значками; при создании категории по названию («Подписка Netflix», «Спотифай») логотип подбирается сам. Готовый пак — [Simple Icons](https://simpleicons.org) (CC0), а убранные из него по просьбе владельцев (Microsoft, Adobe, Amazon, Canva, LinkedIn, Slack, Xbox…) — [CoreUI Brands](https://icons.coreui.io/) и [SVG Logos](https://svgl.app/) (оба CC0). Всё вшито в приложение и работает без интернета: каталог (названия и цвета плиток) — `src/components/serviceData.ts`, пути логотипов — по файлу на группу в `src/components/serviceLogos/` (грузятся лениво, только когда на экране есть сервис группы, поэтому основной файл не растёт). Файлы создаёт `scripts/gen-services.cjs` (как добавить сервис — в шапке скрипта). Названия и логотипы — товарные знаки их владельцев, они нужны только чтобы узнать сервис.
- Таджикские банки и сервисы (Алиф, Душанбе Сити, Эсхата, Амонатбонк, Ориёнбонк, Спитамен, Humo, Tcell, МегаФон, Babilon-M, Zet-Mobile, OSON, Somon и др., 25 значков; список с названиями приложений — в `scripts/gen-tj-services.cjs`) идут в той же вкладке «Сервисы» первыми. Их значки — не векторные логотипы, а значки приложений из Google Play файлами `public/tj/<id>.png`: они лежат в офлайн-кэше, как и остальное. Как добавить: положите квадратный PNG (подойдёт 512×512) в `public/tj/` под именем из списка, выполните `npm i --no-save sharp && node scripts/gen-tj-services.cjs` — скрипт проверит файлы, уменьшит до 192 px и сожмёт, и обновит `src/components/tjData.ts`. Сервис без файла в выборе не показывается (новый сервис: допишите строку в скрипт, положите файл `public/tj/<id>.png` и запустите скрипт); значок МегаФона Таджикистан прислан вручную: приложения для Таджикистана в Google Play нет. Тест следит, чтобы файлы и каталог не расходились.
- Шрифты при сборке всегда остаются отдельными файлами (`assetsInlineLimit` в `vite.config.ts`): политика безопасности не разрешает шрифты, встроенные в CSS.

## Известные ограничения

- **Правки одной записи на двух устройствах объединяются по частям.** Запись делится на независимые части: у операции это «деньги» (сумма, кошелёк, вид, категория, курс — они всегда едут вместе, чтобы не получилась несогласованная запись), «дата», «заметка» и «удаление» (у кошелька — «название», «деньги» — валюта, вид и начальный остаток, «цель накопления» — сумма и срок, «внешний вид» — цвет, значок, порядок, «архив» и «удаление»). Если на телефоне без сети исправили сумму, а на компьютере поменяли заметку, после синхронизации сохранятся **обе** правки, на обоих устройствах. Если же на двух устройствах правили **одну и ту же часть** (например, обе меняли сумму), остаётся правка, сделанная позже. Проверено на моделях и сервере в памяти (см. «Облако проверено…» ниже). Не закрыто: если часы телефона спешат больше чем на 5 минут и ответ сервера при этом потерялся, правка в редком случае может не доехать, поэтому следите, чтобы на устройствах стояло автоматическое время. Чтобы отправка «вслепую» не затёрла чужую правку, которую другое устройство успело записать между получением и отправкой, каждая отправка несёт номер версии записи на сервере (`base_seq`): если там уже записали другое, сервер отвергает всю пачку, а устройство забирает свежее, объединяет по частям и отправляет заново. Для этого в Supabase должна быть актуальная схема (нужно заново выполнить `supabase/schema.sql`); без колонки `base_seq` приложение продолжает работать по-старому, без этой защиты.
- **iPhone не синхронизирует в фоне.** Данные уходят в облако, пока приложение открыто (при запуске, при возврате в приложение, когда появилась сеть, по таймеру и после каждой записи). Закрыли приложение раньше, чем стало «Всё отправлено в облако» — запись остаётся на телефоне и уйдёт при следующем открытии.
- Формат ответов nbt.tj и интернет-источника курсов не проверен вживую (см. «Курсы валют»).
- Формат CSV из Дзен-мани не проверен на настоящем файле (см. «Бюджеты, регулярные платежи, долги, импорт»).
- Автоплатёж, проведённый на устройстве, которое давно не синхронизировалось, может разойтись с «Пропустить», сделанным на другом устройстве: после синхронизации останется то, что новее, и платёж придётся проверить вручную.
- Push-уведомления, вход по коду и замок Face ID проверены только эмуляторами (см. «Вход по коду, замок Face ID и напоминания»). Самое вероятное место сюрпризов на iPhone — обработчик уведомлений в сервис-воркере (`public/push-handler.js`, подключён через `importScripts`) и защита замка от кнопки «назад» (Navigation API есть не везде).
- Облако проверено только на эмуляторе PostgREST и PGlite, не на живом Supabase (см. шаг 6).
- Без сети нельзя войти впервые на новом устройстве. Тот, кто уже входил на этом устройстве, открывает свои данные и без сети.

## Где что лежит

- `src/domain` — деньги, типы, расчёты остатков и курсов
- `src/db` — локальная база на устройстве (Dexie), резервные копии
- `src/sync` — синхронизация с Supabase (`diagnostics*.ts` — служебная диагностика, в интерфейсе сейчас не используется)
- `src/features`, `src/components`, `src/layout` — экраны и интерфейс
- `src/rates` — загрузка курсов
- `src/domain/shopping.ts` и `src/features/shopping` — «Покупки» (расчёты цен и итогов, экран);
- `src/recurring` — расписание и автопроведение регулярных платежей; `src/import` — разбор и план импорта из Дзен-мани
- `src/lock` — замок Face ID (WebAuthn); `src/push` и `public/push-handler.js` — напоминания в приложении; `supabase/functions/send-reminders` — серверная часть напоминаний
- `supabase/schema.sql` — таблицы и правила доступа; `supabase/functions/fetch-rates` — загрузка курсов на сервере; `supabase/functions/parse-shopping` — разбор списка покупок через ИИ; `supabase/functions/parse-expenses` — расходы из диктовки через ИИ
- `vite.config.ts` — сборка, PWA и подстановка адреса Supabase в политику безопасности страницы (`index.html`); `vercel.json` — заголовки ответа
- `e2e` — проверки в настоящем браузере (Playwright)
